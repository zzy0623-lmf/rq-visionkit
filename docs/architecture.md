# 架构说明

RQ-VisionKit 由四个模块（M1–M4）组成，按职责归为三层：

```
┌─────────────────────────────────────────────────────────┐
│ 交互层（低代码）                                          │
│  annotator/web  标注前端（Vue3 单页，Canvas 标注器）        │
│  deployer/      部署控制台（与 M1 共用 FastAPI 进程与前端）   │
├─────────────────────────────────────────────────────────┤
│ 工具层（PC 侧）                                           │
│  annotator/server  采集与标注后端（FastAPI：导入/采集/标注/导出）│
│  converter/        模型适配转换（ONNX→NCNN INT8 CLI + 算子扫描）│
├─────────────────────────────────────────────────────────┤
│ 运行层（端侧）                                            │
│  runtime/pc_sim/   PC 仿真运行时（ncnn-python，HTTP 接口）    │
│  runtime/board/    RK3506 板端运行时（C/C++ + NCNN，同接口）  │
└─────────────────────────────────────────────────────────┘
```

## 关键设计

- **模型与代码分离**：运行时读取 `config.yaml` 加载模型文件，`POST /model/reload`
  无需重启即可切换模型——这是"自定义模型导入"能力的核心。
- **同一 HTTP 接口契约**：PC 仿真版与板端版暴露完全相同的接口
  （`POST /infer`、`GET /health`、`POST /model/reload`），部署控制台不感知底层差异。
- **先仿真后上板**：RK3506 到手前全部基于 PC 仿真（ncnn-python）开发；
  板端受阻超 2 天则退回 QEMU 仿真演示并如实注明。

## 数据流（六步主流程）

采集/导入图片 → 标注（矩形框 + 类别）→ 导出 YOLO 数据集 → 训练/转换
（ONNX → onnxsim → onnx2ncnn/pnnx → ncnn2int8）→ 打包下发（SSH）→ 端侧推理与结果看板。
