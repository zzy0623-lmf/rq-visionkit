# RQ-VisionKit 作品介绍

> 2026 上海开源大赛 · AI+工业软件赛道 · 睿赛德命题
> 面向睿擎工业开发平台（RK3506 开发板）的视觉模型全流程工具链

---

## 1. 背景

睿擎工业开发平台（RK3506，3×Cortex-A7，无 NPU）原生仅提供**一个固定的 YOLOv3 示例**，
开发者要把自己的视觉模型部署到板端，面临三个断层：

- **无数据采集标注**：没有配套的数据集管理与标注工具；
- **无自定义模型导入**：不支持任意训练框架产出的模型（ONNX/PyTorch/Keras）；
- **无低代码部署**：模型下发、升级、结果查看都需要手写脚本或手工操作。

RQ-VisionKit 补齐这条链路，让**自定义视觉模型不写代码即可在 RK3506 上跑起来**。

## 2. 架构

四个功能模块（M1–M4）按职责归为三层：

```
┌─────────────────────────────────────────────────────────┐
│ 交互层（低代码）                                          │
│  annotator/web  标注前端（Vue3 单页，Canvas 标注器）        │
│  deployer/      部署控制台（与 M1 共用 FastAPI 进程与前端）   │
├─────────────────────────────────────────────────────────┤
│ 工具层（PC 侧）                                           │
│  annotator/server  采集与标注后端（FastAPI：导入/采集/标注/导出）│
│  converter/        模型适配转换（ONNX→NCNN INT8 CLI + 算子扫描）│
├─────────────────────────────────────────────────────────┤
│ 运行层（端侧）                                            │
│  runtime/pc_sim/   PC 仿真运行时（ncnn-python，HTTP 接口）    │
│  runtime/board/    RK3506 板端运行时（C/C++ + NCNN，同接口）  │
└─────────────────────────────────────────────────────────┘
```

六步主流程（数据流）：

```
采集/导入图片 → 标注（矩形框+类别）→ 导出 YOLO 数据集 → 训练/转换
（ONNX→onnxsim→pnnx→ncnnoptimize）→ 打包下发（SSH）→ 端侧推理与结果看板
```

## 3. 应用场景

| Demo | 任务 | 说明 |
|---|---|---|
| 主 Demo | NEU-DET 钢材表面缺陷检测（6 类） | 完整六步闭环，YOLOX-Nano 检测 |
| 扩展 Demo | 机械臂智能分拣 | 论文系统迁移，MobileNetV2 分类（降级为「识别+结果显示」） |

## 4. 创新点

1. **全流程低代码**：采集→标注→训练→转换→部署→推理六步，全部经 HTTP 接口或脚本子进程
   完成，零手工改图、零手工命令行。
2. **模型与代码分离**：运行时读 `config.yaml` 加载模型，`POST /model/reload` 免重启切换
   模型——这是「自定义模型导入」能力的核心。
3. **同一 HTTP 接口契约**：PC 仿真版与板端版暴露完全相同的 `/infer`、`/health`、
   `/model/reload`，部署控制台不感知底层差异，本地↔SSH 一键切换。
4. **免调试器升级通道**：发现并落地官方 `app_upgrade` 命令，解决无 DAP-LINK 无法固化 APP
   的死结。
5. **算子兼容处理自动化**：Focus、concat 轴、fp16 截断等非标准算子的自动纠正，
   转换逐元素误差 2.86e-06。

## 5. 性能数据（实测）

| 模型 | 量化 | 精度 | 单帧时延 | 体积 |
|---|---|---|---|---|
| YOLOX-Nano（检测） | FP32 | mAP 6.37% | 10.29 ms | 3.56 MB |
| YOLOX-Nano（检测） | INT8 | mAP 6.71% | 11.61 ms | 945 KB |
| MobileNetV2 六分类 | FP32 | 83.61% | 9.0 ms | 8.86 MB |

转换无损：Keras 84.15% → NCNN 83.61%（Δ-0.54%）；YOLOX NCNN 与 PyTorch 逐元素最大差
2.86e-06。端到端六步联调全链路打通（详见 [e2e-run.md](e2e-run.md)）。

## 6. 开源治理说明

- **许可证红线**：第三方依赖仅接受 Apache-2.0 / MIT / BSD 类，清单见
  [licenses.md](licenses.md)。
- **典型决策**：任务书依赖清单中的 `paramiko` 为 LGPL-2.1，超出允许范围，已改用
  OpenSSH subprocess（`ssh`/`scp`）实现 SSH 下发，零第三方依赖、零许可证风险。
- **数据集合规**：NEU-DET 数据集本体不入库、不再分发，仅非商业研究用途。
- **贡献规范**：Conventional Commits + CI 测试 + 性能数据实测即录（见
  [CONTRIBUTING.md](../CONTRIBUTING.md)）。

## 7. 论文复用声明

参赛者已有一篇在投稿论文（机械臂智能分拣系统）。本项目与论文的关系：

- **复用**：论文训练好的模型与机械臂算法仅作为**被适配/被部署对象**，用于验证工具链能力。
- **新增**：RQ-VisionKit 的全部代码（M1 标注、M2 转换、M3 部署、M4 运行时）均为本赛事期间
  新开发，不包含论文已发表的软件成果。
- **边界**：工具链不依赖论文的任何私有实现；引用论文性能数据（如 RK3588）时均标注来源并
  说明与 RK3506 的差异（无 NPU）。详见 [relation-to-paper.md](relation-to-paper.md)。
